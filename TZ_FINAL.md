Разработать графическое приложение на Java для визуализации и анализа телеметрических данных из бинарных файлов формата KNP.

### 1.2. Технологический стек
- **Язык программирования:** Java

## 2. ВХОДНЫЕ ДАННЫЕ

### 2.1. Файл телеметрии (.knp)
**Формат:** Бинарный файл с последовательностью телеметрических записей (TM-записей)

**Порядок байтов:** Прямой порядок байт (big-endian, старший байт по младшему адресу)

**Структура одной TM-записи (базовая длина 16 байт):**

| Байт | Название поля | Размер | Описание |
|------|---------------|--------|----------|
| 0-1 | Номер параметра | 2 байта | Unsigned short. Если = 0xFFFF, то это служебное сообщение |
| 2-5 | Время формирования | 4 байта | Время в миллисекундах от начала текущих суток (GMT+3) |
| 6 | Размерность | 1 байт | 1-31: формат вывода, 32-255: номер символьной размерности из файла dimens.ion |
| 7 | Атрибут + Тип значения | 1 байт | Младшие 4 бита: тип значения (0-3), старшие 4 бита: атрибут (0-10) |
| 8-15 | Значение параметра | 8+ байт | Зависит от типа значения (см. ниже) |

**Типы значений:**
- **Тип 0 (Long):** 32-разрядное целое число (байты 12-15)
- **Тип 1 (Double):** 64-разрядное вещественное число (байты 8-15)
- **Тип 2 (Code):** Кодовое значение с длиной
  - Байты 10-11: длина кода (2 байта)
  - Байты 12-15: 32-разрядное целое значение
- **Тип 3 (Point):** Массив данных с длиной
  - Байты 8-9: размер элемента (2 байта)
  - Байты 10-11: длина массива в байтах (2 байта)
  - Байты 12+: массив данных (8-4096 байт)

**Служебные сообщения:**
- Если номер параметра = 0xFFFF, то это служебное сообщение
- Длина: 32 байта (для типа "начало сеанса")
- Байт 6: Тип сообщения (0-7)
- Байт 7: Тип значения
- Байты 8-31: Сообщение (8 или 24 байта в зависимости от типа)

**Важно:** Файл начинается со служебного сообщения "начало сеанса" длиной 32 байта.

### 2.2. XML-файл параметров
**Имя файла:** `KNP-173.14.33.58.dat.xml` (или аналогичный)

**Формат:** XML-документ, кодировка обычно UTF-8 или Windows-1251

**Структура:**
XML-файл имеет **иерархическую структуру** с вложенными элементами `<Param>`:

```xml
<TmDat xmlns="http://mcc.rsa.ru/tmo/dat.xsd" version="1.0" 
       translationTime="2017-06-22T14:33:58.228632+03:00" 
       translationVersion="173.14.33.58" idName="KNP">
  <Languages>
    <Language default="true">ru</Language>
  </Languages>
  <Param name="БКА" number="3000">
    <Param name="ПСС" number="3001">
      <Description>Подсистема сбора сообщений</Description>
      <Param name="ЛК0" number="3004">
        <Param name="ИЭТ1" number="1000">
          <Description>Контроль напряжения 6,25В ЛКА1</Description>
        </Param>
        <Param name="0В1" number="1001">
          <Description>Контроль 0В ЛКА1</Description>
        </Param>
        <Param name="БФЧ11" number="1002">
          <Textes>
            <Text number="0">отключено</Text>
            <Text number="1">вкл. норма</Text>
            <Text number="2">вкл. Не норма</Text>
          </Textes>
          <Description>Контроль уровня выходного сигнала...</Description>
        </Param>
        ...
      </Param>
    </Param>
  </Param>
  ...
</TmDat>
```

**Важные особенности:**
- **Иерархическая структура:** Элементы `<Param>` могут быть вложенными на любую глубину
- **Необходимые данные:**
  - Атрибут `name` - имя параметра (может содержать кириллицу)
  - Атрибут `number` - номер параметра (соответствует номеру в TM-записи)
- **Опциональные элементы:**
  - `<Description>` - описание параметра
  - `<Textes>` с `<Text number="...">` - текстовые значения для кодовых параметров

**Парсинг:**
- Использовать стандартные Java XML парсеры (DocumentBuilder, SAX и т.д.)
- **КРИТИЧЕСКИ ВАЖНО:** Необходимо рекурсивно обходить все элементы `<Param>` на всех уровнях вложенности
- Пример рекурсивного парсинга:
  ```java
  private void parseParamElements(NodeList paramNodes, Map<Integer, String> paramMap) {
      for (int i = 0; i < paramNodes.getLength(); i++) {
          Node node = paramNodes.item(i);
          if (node instanceof Element) {
              Element element = (Element) node;
              if ("Param".equals(element.getTagName())) {
                  String name = element.getAttribute("name");
                  String numberStr = element.getAttribute("number");
                  if (!numberStr.isEmpty()) {
                      int number = Integer.parseInt(numberStr);
                      paramMap.put(number, name);
                  }
                  // Рекурсивно обрабатываем вложенные Param элементы
                  NodeList children = element.getChildNodes();
                  parseParamElements(children, paramMap);
              }
          }
      }
  }
  ```
- Обработать возможные проблемы с кодировкой (попробовать UTF-8, затем Windows-1251)

### 2.3. Файл размерностей (dimens.ion)
**Формат:** Текстовый файл, каждая строка - одна размерность

**Кодировка:** Windows-1251 (кириллица)

**Структура:**
- Номер строки (начиная с 1) = номер размерности
- Содержимое строки = текстовое обозначение размерности
- Пример: строка 32 должна содержать "%"
- Пустые строки должны игнорироваться

**Пример содержимого:**
```
(пустая строка)
8
16
32
64
...
B8
B16
...
TEKCT
ASCII
(пустые строки)
%
B
OM
ГРАД C
KM
M/CEK
ГР/CEK
...
```

**Чтение файла:**
```java
BufferedReader reader = new BufferedReader(
    new InputStreamReader(
        new FileInputStream("dimens.ion"), 
        "Windows-1251"  // Важно указать правильную кодировку!
    )
);
String line;
int lineNumber = 1;
Map<Integer, String> dimensionMap = new HashMap<>();
while ((line = reader.readLine()) != null) {
    if (line.trim().length() > 0) {  // Пропускаем пустые строки
        dimensionMap.put(lineNumber, line.trim());
    }
    lineNumber++;
}
reader.close();
```

## 3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

### 3.1. Загрузка данных
- **FR-1.1:** Приложение должно загружать три входных файла:
  - Файл телеметрии (.knp)
  - XML-файл параметров
  - Файл размерностей (dimens.ion)
- **FR-1.2:** **КРИТИЧЕСКОЕ ТРЕБОВАНИЕ:** Все файлы должны читаться **только один раз** при запуске приложения или при явной команде загрузки.
- **FR-1.3:** Данные должны загружаться полностью в память для последующей работы без повторного чтения файлов.
- **FR-1.4:** При ошибке чтения файла должно выводиться информативное сообщение об ошибке с указанием проблемного файла.
- **FR-1.5:** Служебные сообщения должны пропускаться при загрузке (не отображаться в списке параметров).

### 3.2. Главное окно
- **FR-2.1:** Главное окно должно иметь заголовок с названием приложения (например, "Анализатор телеметрических данных").
- **FR-2.2:** Окно должно быть масштабируемым и иметь разумные размеры по умолчанию (рекомендуется 1200x800 пикселей).
- **FR-2.3:** Окно должно корректно обрабатывать закрытие (завершение работы приложения).

### 3.3. Панель параметров (левая часть)
- **FR-3.1:** Слева должна располагаться панель прокрутки со списком всех **уникальных** параметров, присутствующих во входном файле.
- **FR-3.2:** Список параметров должен отображать полные имена параметров (из XML-файла), а не только номера.
- **FR-3.3:** При наведении курсора на параметр должно отображаться его полное имя в виде tooltip (если имя длинное и обрезано).
- **FR-3.4:** Список должен поддерживать прокрутку для большого количества параметров.
- **FR-3.5:** Список должен поддерживать выбор одного параметра (single selection).

### 3.4. Отображение значений параметра (правая/центральная часть)
- **FR-4.1:** При выборе параметра из списка должны отображаться **все** его значения из входного файла.
- **FR-4.2:** Значения должны отображаться в отдельной области окна (правая часть или центральная область).
- **FR-4.3:** Для каждого значения должно отображаться:
  - **Время измерения** в формате: часы:минуты:секунды.миллисекунды
  - **Значение** с учетом типа:
    - Тип 0 (Long): десятичное целое число
    - Тип 1 (Double): вещественное число
    - Тип 2 (Code): двоичное представление (например, "0101") и длина кода
    - Тип 3 (Point): длина массива (сам массив можно не показывать)
  - **Размерность** (текстовое обозначение из файла dimens.ion)
  - **Атрибут** (опционально, можно не показывать)
- **FR-4.4:** Отображение должно быть в виде таблицы (JTable) с колонками:
  - Время
  - Значение
  - Размерность
- **FR-4.5:** Таблица должна поддерживать прокрутку для большого количества значений.
- **FR-4.6:** Таблица должна поддерживать сортировку по колонкам (опционально).

### 3.5. Статистика
- **FR-5.1:** Должна быть кнопка "Статистика" для отображения общей информации о данных.
- **FR-5.2:** Статистика должна включать:
  - Общее количество TM-записей в файле (включая служебные)
  - Количество полезных TM-записей (без служебных)
  - Количество уникальных TM-параметров
  - Диапазон времени измерений (минимальное и максимальное время)
  - Размер входного файла
  - Дополнительные метрики (на усмотрение разработчика)

### 3.6. Интерфейс пользователя
- **FR-6.1:** Интерфейс должен быть визуально привлекательным и современным.
- **FR-6.2:** Должна быть реализована удобная навигация между элементами интерфейса.
- **FR-6.3:** Все элементы управления должны быть интуитивно понятными.
- **FR-6.4:** Рекомендуется использовать меню (File → Open, Help → About) или кнопки для загрузки файлов.

## 4. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

### 4.1. Производительность
- **TR-1.1:** **КРИТИЧЕСКОЕ ТРЕБОВАНИЕ:** Все входные файлы должны читаться один раз при загрузке.
- **TR-1.2:** Приложение должно эффективно работать с файлами размером до нескольких сотен мегабайт.
- **TR-1.3:** Операции выбора параметра и отображения значений должны выполняться без заметных задержек (< 1 секунды).
- **TR-1.4:** Загрузка файлов должна выполняться в отдельном потоке (SwingWorker) для предотвращения блокировки UI.

### 4.2. Обработка данных
- **TR-2.1:** Парсинг бинарного файла должен корректно обрабатывать порядок байтов (big-endian).
- **TR-2.2:** Формирование номера параметра из двух байтов:
  ```java
  int number = ((buff[0] << 8) & 0xFF00) | (buff[1] & 0xFF);
  ```
- **TR-2.3:** Должна быть реализована валидация данных при чтении файлов.
- **TR-2.4:** Обработка ошибок должна быть надежной и информативной.
- **TR-2.5:** Корректная обработка TM-записей типа Point с переменной длиной.
- **TR-2.6:** **Парсинг XML-файла:** Необходимо рекурсивно обходить все элементы `<Param>` на всех уровнях вложенности для извлечения всех пар (номер, имя).
- **TR-2.7:** **Чтение dimens.ion:** Обязательно использовать кодировку Windows-1251 при чтении файла для корректного отображения кириллицы.
- **TR-2.8:** При парсинге XML рекомендуется создать Map<Integer, String> для быстрого поиска имени параметра по номеру:
  ```java
  TreeMap<Integer, String> paramMap = new TreeMap<>();
  // После парсинга XML:
  String paramName = paramMap.get(parameterNumber);
  if (paramName == null) {
      paramName = "Параметр " + parameterNumber;  // Fallback для неизвестных параметров
  }
  ```

### 4.3. Структура проекта
- **TR-3.1:** Код должен быть организован в модули/пакеты согласно принципам объектно-ориентированного программирования.
- **TR-3.2:** Должно быть разделение на слои:
  - **Слой работы с данными (Data Layer):**
    - Классы для чтения и парсинга .knp файла
    - Классы для чтения файла dimens.ion
    - Классы для парсинга XML-файла параметров
    - Модели данных для хранения информации в памяти
  - **Слой бизнес-логики (Business Layer):**
    - Классы для обработки данных
    - Классы для статистики
  - **Слой представления (Presentation Layer):**
    - GUI компоненты на Swing
    - Обработчики событий

### 4.4. Модели данных
- **TR-4.1:** Рекомендуемая структура классов:
  ```java
  // Базовый класс для TM-записи
  public class TmRecord {
      int parameterNumber;
      String parameterName;
      long time;  // в миллисекундах
      String dimension;
      int attribute;
      int valueType;
      // значение зависит от типа
  }
  
  // Наследники для разных типов значений
  public class TmLong extends TmRecord {
      long value;
  }
  
  public class TmDouble extends TmRecord {
      double value;
  }
  
  public class TmCode extends TmRecord {
      int codeLength;
      long value;
  }
  
  public class TmPoint extends TmRecord {
      int elementSize;
      int arrayLength;
      byte[] data;
  }
  ```

## 6. АЛГОРИТМ РАБОТЫ ПРИЛОЖЕНИЯ

### 6.1. Инициализация
1. Запуск приложения
2. Отображение главного окна
3. Предложение загрузить файлы (через меню или диалог)

### 6.2. Загрузка файлов
1. Пользователь выбирает три файла через диалог выбора файлов
2. В фоновом потоке (SwingWorker):
   - **Чтение XML-файла:**
     - Парсинг XML с использованием DocumentBuilder
     - **Рекурсивный обход всех элементов `<Param>`** на всех уровнях вложенности
     - Создание Map<Integer, String> (номер → имя параметра)
   - **Чтение файла dimens.ion:**
     - Чтение с кодировкой Windows-1251
     - Создание Map<Integer, String> (номер строки → размерность)
     - Пропуск пустых строк
   - **Чтение .knp файла:**
     - Пропуск служебных сообщений (номер параметра = 0xFFFF)
     - Парсинг каждой TM-записи
     - Создание объектов TmRecord и их сохранение в структуре данных
     - Связывание записей с именами параметров из XML и размерностями из dimens.ion
3. После загрузки:
   - Заполнение списка уникальных параметров (с именами из XML)
   - Отображение статистики (опционально)

### 6.3. Работа с данными
1. Пользователь выбирает параметр из списка
2. Приложение фильтрует все TM-записи по выбранному параметру
3. Отображение отфильтрованных записей в таблице

### 6.4. Статистика
1. Пользователь нажимает кнопку "Статистика"
2. Открывается диалоговое окно (JDialog) со статистикой
3. Отображение всех метрик

## 11. СПРАВОЧНАЯ ИНФОРМАЦИЯ

### 11.1. Формулы преобразования данных

**Номер параметра из двух байтов:**
```java
int number = ((buff[0] << 8) & 0xFF00) | (buff[1] & 0xFF);
```

**Время из 4 байтов (big-endian):**
```java
long time = ((long)(buff[2] & 0xFF) << 24) |
            ((long)(buff[3] & 0xFF) << 16) |
            ((long)(buff[4] & 0xFF) << 8) |
            ((long)(buff[5] & 0xFF));
```

**Тип значения и атрибут из байта 7:**
```java
int attribute = (buff[7] >> 4) & 0x0F;  // старшие 4 бита
int valueType = buff[7] & 0x0F;          // младшие 4 бита
```

**Преобразование времени в формат ЧЧ:ММ:СС.мс:**
```java
long totalMs = time;  // время в миллисекундах от начала суток
long hours = totalMs / 3600000;
long minutes = (totalMs % 3600000) / 60000;
long seconds = (totalMs % 60000) / 1000;
long milliseconds = totalMs % 1000;
String timeString = String.format("%02d:%02d:%02d.%03d", hours, minutes, seconds, milliseconds);
```

### 11.2. Значения атрибутов
- 0 - норма
- 1 - не норма нижняя
- 2 - внимание нижнее
- 3 - внимание верхнее
- 4 - не норма верхняя
- 8 - недостоверное значение
- 9 - значение вне диапазона тарировочной характеристики
- 10 - значение вне диапазона калибровочных уровней ("Зашкаливание")

### 11.3. Примеры кода для чтения файлов

**Чтение XML-файла с рекурсивным парсингом:**
```java
import javax.xml.parsers.DocumentBuilder;
import javax.xml.parsers.DocumentBuilderFactory;
import org.w3c.dom.Document;
import org.w3c.dom.Element;
import org.w3c.dom.Node;
import org.w3c.dom.NodeList;
import java.util.TreeMap;

public Map<Integer, String> parseXmlFile(String xmlFilePath) throws Exception {
    TreeMap<Integer, String> paramMap = new TreeMap<>();
    
    DocumentBuilderFactory factory = DocumentBuilderFactory.newInstance();
    DocumentBuilder builder = factory.newDocumentBuilder();
    Document doc = builder.parse(new File(xmlFilePath));
    
    NodeList paramNodes = doc.getElementsByTagName("Param");
    parseParamElementsRecursive(paramNodes, paramMap);
    
    return paramMap;
}

private void parseParamElementsRecursive(NodeList nodes, Map<Integer, String> paramMap) {
    for (int i = 0; i < nodes.getLength(); i++) {
        Node node = nodes.item(i);
        if (node instanceof Element) {
            Element element = (Element) node;
            if ("Param".equals(element.getTagName())) {
                String name = element.getAttribute("name");
                String numberStr = element.getAttribute("number");
                if (!numberStr.isEmpty() && !name.isEmpty()) {
                    try {
                        int number = Integer.parseInt(numberStr);
                        paramMap.put(number, name);
                    } catch (NumberFormatException e) {
                        // Игнорируем невалидные номера
                    }
                }
                // Рекурсивно обрабатываем вложенные Param элементы
                NodeList children = element.getChildNodes();
                parseParamElementsRecursive(children, paramMap);
            }
        }
    }
}
```

**Чтение файла dimens.ion с правильной кодировкой:**
```java
import java.io.BufferedReader;
import java.io.FileInputStream;
import java.io.InputStreamReader;
import java.util.HashMap;
import java.util.Map;

public Map<Integer, String> readDimensionFile(String filePath) throws Exception {
    Map<Integer, String> dimensionMap = new HashMap<>();
    
    BufferedReader reader = new BufferedReader(
        new InputStreamReader(
            new FileInputStream(filePath), 
            "Windows-1251"  // Критически важно!
        )
    );
    
    String line;
    int lineNumber = 1;
    while ((line = reader.readLine()) != null) {
        String trimmed = line.trim();
        if (!trimmed.isEmpty()) {  // Пропускаем пустые строки
            dimensionMap.put(lineNumber, trimmed);
        }
        lineNumber++;
    }
    reader.close();
    
    return dimensionMap;
}
```

**Обработка отсутствующих параметров:**

String dimension = dimensionMap.get(dimensionNumber);

    dimension = "размерность " + dimensionNumber;  // Fallback
